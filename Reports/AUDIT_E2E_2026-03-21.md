## 2. README / Descriere proiect

# STT Module - Speech-to-Text for Romanian Medical Dictation

## Overview
Generic, reusable Speech-to-Text module with native Romanian support, designed for medical/dental professionals. Supports multiple STT providers with on-premise deployment for GDPR compliance.

## Key Features
- **Multi-provider support**: Switch between Whisper (self-hosted), Vatis Tech, Deepgram, OpenAI, Azure, Google Cloud
- **Romanian-first**: Optimized for Romanian language with diacritics support
- **Medical/Dental domain**: Custom vocabulary, terminology correction, SOAP note templates
- **On-premise deployment**: Zero data leaves client infrastructure
- **Real-time + Batch**: Live transcription and file upload
- **GDPR compliant**: Encrypted credentials, audit logs, configurable audio retention

## Target Users
- Medical doctors (dictating patient reports)
- Dentists (hands-free documentation during procedures)

## Tech Stack
- **Frontend**: Next.js 14 (App Router), React 18, Tailwind CSS, shadcn/ui
- **Backend**: Next.js API Routes, WebSocket (Socket.io/ws)
- **Database**: SQLite via Prisma ORM
- **STT Engines**: faster-whisper (local), API providers (configurable)
- **Audio**: ffmpeg, MediaRecorder

### 4.3 Calitatea Codului

**Puncte pozitive:**
- Arhitectura Strategy Pattern pentru provideri este bine implementata - abstract class `STTProvider`, manager cu cache, factory method.
- Validare request cu Zod in toate endpoint-urile critice (transcribe, reports, settings).
- Prisma client singleton corect implementat (pattern standard Next.js cu `globalThis`).
- TypeScript cu interfete clare in `src/types/stt.ts`.
- `force-dynamic` prezent pe endpoint-urile care citesc din DB in GET (settings, providers, whisper-server).
- Tratare erori consistenta in API routes (try/catch, coduri HTTP corecte).
- Logging cu `console.error` in toate catch-urile.

**Probleme identificate:**
- `AudioSettings.tsx`: toate setarile sunt state local React, nu se salveaza nicaieri. Schimbarea sample rate-ului sau formatului nu are efect real.
- `SettingsPage` - tab Templates si Vocabulary: componentele `TemplatesTab` si `VocabularyTab` sunt definite in acelasi fisier cu date hardcoded. Butoanele "Adauga", "Sterge", "Import CSV", "Export CSV" nu au `onClick` conectat la API.
- `handleSaveReport` in `record/page.tsx` foloseste `alert()` pentru confirmare succes — pattern nerecomandat in productie.
- `history/page.tsx` foloseste `confirm()` pentru confirmare stergere — inconsistent cu restul aplicatiei care ar trebui sa foloseasca dialog modal.
- `Badge` in `history/page.tsx` foloseste `variant="success"` si `variant="warning"` care nu exista in componenta shadcn/ui standard — risc de erori TypeScript sau afisare gresita.
- `record/page.tsx`: template-ul selectat din UI nu este trimis in request-ul de transcriptie si nu influenteaza procesarea.
- `VatisTechProvider.transcribe()`: trimite intotdeauna `audio/wav` ca Content-Type indiferent de formatul real al fisierului.
- `src/lib/audio/manager.ts` este listat in directoare dar nu are implementare documentata (placeholder pentru Phase 2).

**TODO-uri identificate:**
- `whisper-server/route.ts` linia 91: `setupReady: true, // venv exists check happens client-side` — verificarea este omisa.
- `reports/[id]/page.tsx` linia 84: `// eslint-disable-next-line react-hooks/exhaustive-deps` — hook dependency suprimata manual.
- Comentariul din `transcribe/stream/route.ts` documenteaza explicit ca WebSocket nu este implementat (Phase 3).

### 4.5 Starea Autentificarii, Bazei de Date si API-urilor Externe

**Autentificare**: Absenta. Nu exista middleware de autentificare, sesiuni, JWT, sau orice alt mecanism. Planificata pentru Phase 4.

**Baza de Date (SQLite/Prisma)**:
- Schema completa cu 5 modele: `Setting`, `Transcription`, `Report`, `Template`, `CustomVocabulary`
- Migratie initiala aplicata (`20260312175037_init`)
- Pattern singleton Prisma corect pentru Next.js (evita multiple conexiuni in dev)
- Fisier DB la `prisma/data/stt.db` (cale configurata prin `DATABASE_URL` in `.env`)
- SQLite: adecvat pentru single-user on-premise, nu pentru multi-user concurent

**API-uri Externe**:
- **OpenAI Whisper**: Necesita `OPENAI_API_KEY` in `.env` sau configurat din UI. SDK `openai@4.67` instalat.
- **Deepgram**: Necesita `DEEPGRAM_API_KEY`. SDK `@deepgram/sdk@3.8` instalat.
- **Vatis Tech**: Necesita `VATIS_TECH_API_KEY`. Implementat cu polling pentru operatii async. Fara SDK dedicat (fetch direct).
- **Whisper Local**: Fara API key. Necesita Python venv + faster-whisper instalat manual via `whisper/setup-whisper.bat`. Server HTTP pe `127.0.0.1:8787`. Auto-start implementat in `/api/transcribe`.

### Top 5 Probleme Critice (Prioritizate)

**1. [P1 - BLOCKER] ffmpeg / convertor audio absent**
Inregistrarile din browser produc audio WebM (Opus). Providerii API (OpenAI, Deepgram, Vatis Tech) accepta WebM dar whisper-local primeste fisierul "as-is" si detectia magicbytes din `whisper-local.ts` functioneaza numai pentru formatele standard. `src/lib/audio/manager.ts` este placeholder. Exista risc real ca transcrierea sa esueaze sau sa produca rezultate incorecte fara conversie WAV explicita.

**2. [P1 - BLOCKER] Fara autentificare**
Orice persoana cu acces la portul aplicatiei poate citi toate transcrierile medicale, modifica rapoartele, obtine API keys din interfata de configurare si controla serverul Whisper. Inacceptabil pentru date medicale chiar si in deployment local. Minim necesar: parola simpla sau HTTP Basic Auth.

**3. [P2 - HIGH] Vocabular si Templates neconectate la backend**
Butoanele "Adauga", "Sterge", "Import CSV", "Export CSV" din tab-ul Vocabular nu au onClick. Tab-ul Templates afiseaza carduri hardcoded. API-urile exista si sunt implementate dar UI nu le foloseste. Aceasta creeaza iluzia unei functionalitati care de fapt nu functioneaza.

**4. [P2 - HIGH] Setarile Audio nu se persista**
Sample rate, format si optiunile noise reduction/auto-delete sunt state local React si se pierd la refresh. Inregistrarea audio va folosi intotdeauna setarile implicite ale browserului indiferent de ce seteaza utilizatorul in UI.

**5. [P3 - MEDIUM] Lipsa CORS si rate limiting**
Fara configurare CORS explicita, request-urile cross-origin pot fi un vector de atac. Fara rate limiting, endpoint-ul POST /api/transcribe poate fi abuzat (fisiere mari, multe request-uri), epuizand creditele API ale providerilor platiti.
